# Architecture

`app/` contains App Router pages and versioned Node API handlers. `components/` contains the responsive terminal, scanner, analysis, charts, evidence, and workspace. Server-only modules are imported exclusively from server entry points. The independent browser receipt verifier imports only `lib/canonical.ts`.

`lib/providers/market.ts` validates and normalizes DexScreener and GeckoTerminal. Independent requests run concurrently. Shared HTTP utilities provide 10-second timeouts, one jittered retry on transient errors, deduplication, bounded caches, original collection time, and host-level 429 pauses. Market data caches for 30 seconds; quotes cache for 5 seconds. These are per-process caches, not durable history. Jupiter requests are serialized at 0.5 RPS keyless / conservative 1 RPS keyed in each process. Shared user/IP limits use an atomic Supabase function. Cross-instance provider-global quota coordination is a documented scaling priority.

`lib/engine.ts` resolves token metadata, optionally validates mint account owner and decimals via RPC, chooses a user-selected pool or a deepest-reported-reserve reference, constructs the exact atomic amount, requests a quote without a taker, fetches an available USDC/USD observation, computes values, and assigns diagnostics. Every failed provider remains represented. Selecting a reference does not constrain Jupiter routing. A missing matching pool or source observation time suppresses direct price deviation.

`lib/calculations.ts` uses 100-digit Decimal arithmetic and centrally versioned rules. `lib/solana.ts` uses the current `@solana/addresses` package and BigInt unit conversions. JSON monetary values are strings; floating-point conversions are restricted to presentation, sorting, charting, or threshold comparisons.

Demo scenarios are explicit inputs with `mode=demo`. They use deterministic fictional market adapters and a size-sensitive illustrative quote curve. All calculation, visualization, receipt, and verification paths are shared. Demo data never enters production analytics. Browser-local state and ephemeral demo receipt memory are separate from Supabase. Snapshot records carry mode checks and live scan/receipt JSON constraints.

Supabase Auth uses email OTP/magic links with PKCE and cookie exchange. Server handlers call `auth.getUser()` and enforce owner IDs in addition to RLS. Private data cannot be read anonymously. Authenticated reads/writes use user-session clients, while system writes use a server-only service-role client. Public receipts and public keys are readable; no private signing key is stored in the database. Account UI uses Supabase's browser client and query invalidation.

Receipts are issued from fresh **server-collected** analyses, not client-supplied price/quote fields. They use canonical JSON, SHA-256, and Ed25519. Hashes cover content including identity, mode, timestamps, token, pool, provider snapshots, quote metadata, calculation, diagnostics and limitations. Demo keys are ephemeral. Production keys are provisioned through environment secrets, registered immutably by key ID, and retained for verification. PostgreSQL triggers deny updates/deletes to issued content.

Normalized schema includes token/pool identity, snapshots, comparisons, quotes, scans, watchlists/items, rules/events, receipts/public keys, monitoring jobs/runs and request buckets. Provider payloads are normalized summaries, not full raw upstream responses. `recordAnalysis` stores identity records, exact quotes, evidence envelopes and deduplicated retrieval summaries. Personal historical charts use actual scan groups with matching mode, mint, pool, exact quantity and conversion context; identical cached quote timestamps are deduplicated.

Monitoring is a protected Node route invoked by Supabase Cron/pg_net. Alert triggers create a job for a user/mint. Workers lease up to three due jobs with `FOR UPDATE SKIP LOCKED`, collect real analyses sequentially, compare previous successful observations, evaluate rules, deduplicate events by rule/time window plus rolling cooldown, and optionally deliver email. Runs retain errors and durations. Leases recover after 5 minutes. Scheduled retention removes non-receipt history. Job-level idempotency is stronger than delivery-level idempotency; transactional outbox/recovery messages remain future work.

The analytics function aggregates real stored retrievals, excludes demo by constraint, withholds samples below 10 per source, and reports coverage/latency/unknown-source-time metrics. Same-pool price deviation is computed only on source-time-aligned observations; there is no independent truth benchmark.
